# ets-tables

ETS table inventory. Source of truth: `lib/smalt/store_tables.ex`
(`Smalt.StoreTables`, generated by `mix smalt.gen` from the
`smalt:StoreTable` ontology rows and replay-identity test-fenced);
`Smalt.Store` consumes it (`@tables Smalt.StoreTables.table_names()` —
do not re-introduce a local `@tables` list in store.ex). All core tables
are `:ordered_set, :public, :named_table, read_concurrency: true`, created
idempotently by `Smalt.Store`; keys are lowercased full ARM id strings (or
id-shaped paths) so `list_prefix/2` scans are deterministic and TF-stable.

Count (as of 2026-10-19 @ HEAD 6681746): **53 distinct named `:smalt_*`
tables** — 33 owned tables (`Smalt.StoreTables.table_names/0`) + 19 shadow
tables (`shadow_tables/0`, owner-managed, never swept) = 52 registered
atoms, plus the lazily-created `:smalt_egress_guard`
(`egress_router.ex:3799`) which sits outside the generated registry.

## DETS mirror (restart persistence)

`Smalt.Store.DetsMirror` (`lib/smalt/store/dets_mirror.ex`) is an opt-in,
poll-based `:dets` persistence mirror beside `Smalt.Store`. Default table
set is the generated `Smalt.StoreTables.persisted_tables/0` (6 tables:
`:smalt_blobs`, `:smalt_cosmos_docs`, `:smalt_event_messages`,
`:smalt_ledger_meta`, `:smalt_ledger_transactions`, `:smalt_resources`).
Mechanics:

- Per-table `.dets` file under `:dir` (default `tmp/dets`); the mirror
  `:ets.tab2list/1`s each table on an interval and upserts `{key, value}`
  rows. While hot, ETS stays the source of truth; `restore/0` replays
  mirrored rows back, skipping keys already present.
- **Drift window (honest limits)**: poll-based, not subscribe-based —
  writes within one sync interval before a crash are not mirrored, and
  rows deleted from ETS are never removed from the mirror, so a restored
  table is a union, not a snapshot.
- **`open_typed` repair**: un-closed `.dets` files after `kill -9` are
  healed by the typed open path (`open_typed/3`); repair is witnessed by
  telemetry `[:smalt, :store, :dets_repaired]`; corruption repair cannot
  heal (flipped header, `:not_a_dets_file`) fails closed.

## Cascade laws (the census)

Three cascade mechanisms exist; they are distinct:

1. **RG cascade** (`arm_gateway/router.ex`, D127 decision): resource-group
   delete sweeps contained resources AND blob containers in the group. This
   cascade is not an implementation of per-container DELETE — the D127
   product gap stays open (WRAP_LEDGER item 4 wording, on record).
2. **FR-6 data-plane drop** (`blob_storage.drop_account_data/1`): sweeps
   `:smalt_blob_containers`, `:smalt_blobs`, `:smalt_blob_policy`,
   `:smalt_blob_blocks`, `:smalt_blob_snapshots` by `"account/"` prefix,
   guarded per-table on `:ets.info` so un-booted lazy tables are loud-safe.
   Note: "FR-6" itself carries no on-disk referent outside receipts
   (exhaustive grep 2026-10-16, WRAP_LEDGER item 4).
3. **Terraform destroy** (`enclave/state.ex destroy/1`): reverse-topological
   DELETE walk through the real `Router.call/2` (deepest path-segment count
   first), polls 202 LROs to terminal, verifies 404 per id, then asserts zero
   residue over resource-bearing tables. `@metadata_tables` (listed above)
   are legitimately exempt: LRO history, subscription roots, counters, lock
   tokens, checkpoints, baselines.

Mutations that must be atomic (CAS/etag, cas_delete, sequence assignment) are
serialized through `Smalt.Store`'s GenServer (`compare_and_swap/4`,
`compare_and_swap_delete/3`, `next_seq/3`); SB claim/settle transitions
serialize through `QueueStore`'s own GenServer; EH sequencing through
`EventHubs.Server`.
