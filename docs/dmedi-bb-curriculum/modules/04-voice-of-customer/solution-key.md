# Module 04 — Solution Key

Every number below re-derives from `data/kano-responses.csv` (SEED 20261104) via
`python3 data/compute.py` (exit 0). Derivations are shown, not asserted.

## E1
(a) (F=A, D=A) → **Q** (questionable): respondent says they "like" both presence and
absence — the pair carries no class information, discarded before tallying.
(b) (F=M, D=M) → **R** (reverse): the customer wants the attribute absent.
(c) (F=A, D=I) → **O** (one-dimensional / ordinal).

## E2
1. The evaluation table is a lookup, not an arithmetic model: pairs like (M,A) and
   (A,M) both map to O, but their score *difference* is zero under the averaging
   scheme — the scheme destroys the very asymmetry Kano exists to expose.
2. Averaging assumes interval-scale answers; the five options are ordinal. A
   respondent answering (A,I) and one answering (M,A) contribute equal "distance"
   in an average, but one is a satisfier pattern and the other a dissatisfier
   pattern. The table method also discards Q responses, which an average silently
   contaminates.

## E6
Points formula: points_i = (n + 1 − rank_i); ×100 points = points_i / Σpoints × 100,
Σpoints = n(n+1)/2 = 28. Ranks → points: CR-a 7, CR-b 5, CR-c 6, CR-d 3, CR-e 4,
CR-f 1, CR-g 2 (sum 28 ✓). ×100: 25.0, 17.86, 21.43, 10.71, 14.29, 3.57, 7.14.
These do NOT sum to exactly 100 after rounding (sum = 100.00 exactly here, but the
lawful fixed-point method is: allocate rounded values, then adjust the largest
weight by the residual so the integers sum to exactly 100). With largest-remainder
allocation: 25, 18, 21, 11, 14, 4, 7 → sum = 100 ✓.

## E7
```python
import csv
from collections import Counter
KANO = {("A","M"):"A", ("A","I"):"O", ("M","A"):"O", ("M","I"):"M",
        ("I","A"):"R", ("I","M"):"M", ("I","I"):"I"}
rows = [r for r in csv.DictReader(open("data/kano-responses.csv")) if r["kano_id"]=="K-10"]
cls = Counter(KANO[(r["func"], r["dys"])] for r in rows)
assert cls.most_common(1)[0][0] == "I", f"K-10 majority moved: {cls}"
```
It must read the CSV, not the generator dict, because the dict is the generator's
INTENT; the CSV is the artifact the course consumes. A generator edit that changes
fill behavior (e.g., the fill pool) can flip the majority while the dict still says
"I" — reading the dict would make the check vacuous. Assert on final state (the
artifact), never on the authoring claim.

## E10
K-03 counts (from compute.py): M=8, I=1, Q=2, A=1. The two (A,A)=Q rows are
discarded per the Part B rule.
- With discard (as-generated, n=10): M8 I1 A1 → majority **M**; SI = 1/10 = 0.100;
  DSI = −8/10 = −0.800.
- Without discard (n=12): M8 I1 A1 Q2 → majority still **M** (8 of 12), but
  SI = 1/12 = 0.083, DSI = −8/12 = −0.667 — the indices shift and the class
  information the Q pairs carried (none) is now counted as if it were evidence.
  Majority is robust here; the indices are not. Lesson: discard Q, then compute.
