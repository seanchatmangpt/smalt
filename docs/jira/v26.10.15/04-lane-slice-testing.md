# 04 — Lane Slice Testing (Post-Merge Court as THE Gate)\n\n**Release**: v26.10.15 · **Lane**: 04-lane-slice-testing · **Status**: PLANNED\n**Witnessed context**: v26.10.14 receipts — parallel lanes each ran full suites (`just court` ≈ 3 min each, many lanes), starving the fleet on substrate + compile contention; lanes queued 10-20+ minutes behind each other. Meanwhile the actual integration truth came from the coordinator's `just court-x2` anyway, and the compile-freeze SLA (see receipts: 01, 04, 07, 08, 10, 20, dod-11) existed precisely because lanes broke the shared compile mid-run. Full suites per lane bought nothing integration-wise; they bought queue time.\n**Environment**: Elixir/Mix 1.19.5, OTP 28, macOS (darwin 25.2.0).\n\n## 1. Problem\n\nThe v26.10.14 lane protocol had every lane run the full verification ladder locally before landing. Three failures:\n\n1. **Fleet starvation.** N lanes × full court serializes on substrate (Store ETS, ports, `config/test.exs` env) and on compile. Lanes waited 10-20+ min; court is ~3 min × many lanes.\n2. **False assurance.** Integration truth was decided by the coordinator's `court-x2` regardless. A lane's own full-suite green proved nothing the coordinator's run didn't re-prove — but every lane paid for it.\n3. **Shared-compile breakage.** Lanes compiling a tree another lane had half-edited is why the compile-freeze SLA was needed at all. The SLA treats the symptom; slice-scoped runs reduce the exposure.\n\nRoot cause: lanes ran the **coordinator's** gate (whole-repo) instead of an **owned-slice** gate (their files only). Two different questions, one expensive answer.\n\n## 2. Move\n\n- Each work-order doc gains an explicit **`tests:` field** listing its owned test slice (files/tags) — the slice contract.\n- New recipe **`just slice <wo-id>`**: parses the WO doc's `tests:` field, runs the compile gate, then runs only that slice.\n- **`just court-x2` remains the single integration gate, run post-merge by the coordinator.** Lanes stop running it. Slice green ≠ landed.\n- Shared-seam lanes (per `docs/jira/v26.10.14/RESOLUTIONS.md`) escalate to full `test-offline`: their seams touch code slices cannot isolate.\n\n**Constraint**: the compile-freeze SLA is preserved unchanged. The compile gate in `just slice` *front-loads* it — a lane that would break the shared compile fails its own slice run in seconds instead of poisoning another lane's 3-minute court.\n\n## 3. Spec\n\n### 3.1 Slice contract — the `tests:` field in WO docs\n\nEvery WO doc in `docs/jira/v26.10.15/` gains a fenced block:\n\n```\n## tests:\n- test/store/lens7_restore_test.exs\n- test/data_plane/cosmos_test.exs:restart_poll\n```\n\nGrammar:\n- One file path per line, repo-relative; optional `:tag` suffix = `--only <tag>`.\n- Paths are paths: the recipe passes them to `mix test <paths...>`; no globs, no shell expansion.\n- A WO with no owned tests declares `tests: none (court-x2 gated)` — an empty list is a declaration, not an omission.\n- `_LANES.md` (v26.10.15 edition, mirrored from v26.10.14 with the ownership table) remains the authority for *who owns what*; the per-WO `tests:` field is the machine-readable projection of it. If they disagree, `_LANES.md` wins and the WO doc is the bug.\n\n### 3.2 `just slice <wo-id>`\n\nNew `justfile.d/08-slice.just` (numbering follows the existing `NN-name.just` convention; `07-court-x2.just` is imported by `justfile:218`):\n\n1. **Resolve**: locate `docs/jira/v26.10.15/<wo-id>-*.md` by id prefix; extract the `## tests:` block; error loud on missing doc, missing block, or unresolvable path.\n2. **Compile gate**: run the existing compile check (warnings-as-before, same recipe the court uses) **against the shared `_build`** before any test runs. Non-zero → abort with the compile output. This is the SLA enforcement point: a broken shared compile stops *this lane* here, it does not reach other lanes.\n3. **Run**: `mix test <resolved paths>` with `MIX_BUILD_ROOT` per whatever lane 03 lands (contract-keyed tree). The slice recipe must not pin its own build root — it defers to the cache layer.\n\nExit semantics: 0 = slice green; non-zero = slice red or contract error. Slice output stays small — no bench, no census, no wire tier beyond listed files.\n\n### 3.3 What still requires the full suite (shared seams)\n\nPer `RESOLUTIONS.md`, these surfaces are shared across lanes and cannot be slice-isolated; their WOs declare full-suite escalation:\n\n| Seam (RESOLUTIONS.md) | Lanes | Escalation |\n|---|---|---|\n| S1 `ensure_store_up/0` / store lifecycle | 01, 02 | full `test-offline` |\n| S3 `egress_router.ex` split | 06, 19 | full `test-offline` + the shared regression set named in S3 (`test/wire/egress_wire_test.exs`, `test/data_plane/{cosmos,key_vault_actions,audit_planes}_test.exs`) |\n| `application.ex` (S1-adjacent; one additive child, lane 05) | 05 | full `test-offline` |\n| `test/test_helper.exs` (01 helper / 13 tag exclusions) | 01, 13 | full `test-offline` |\n\nTelemetry (lane 03 of v26.10.14) is on the list too: its total test filter and cross-window sums are cross-cutting. Rule of thumb: **if the WO's files are imported by anything outside its lane, it is a seam lane — escalate.**\n\nSeam lanes MAY also run their slice (`just slice`) for fast iteration; the escalation is additive, not a replacement.\n\n### 3.4 Escalation rule — slice green ≠ landed\n\n- A lane's landing condition is: slice green (or escalated full `test-offline` green) + receipt written.\n- **The lane does not run `court` or `court-x2`.** Integration is the coordinator's act: coordinator runs `just court-x2` post-merge; two consecutive greens are the only DoD.\n- If `court-x2` red after a merge, the coordinator bisects by re-running the merged lanes' slices first (cheap), then full tiers — the slice contract makes lane-level blame a lookup, not a hunt.\n\n## 4. Falsifier\n\n**Seeded cross-suite regression**: pick two independent lanes (e.g. auth slice + cosmos slice). Seed a regression that only manifests cross-suite — e.g. change a shared helper's return shape that auth's slice mocks but cosmos's slice exercises, or rename a function cosmos calls that auth's slice files never import. Expected:\n\n- Both lanes' `just slice` runs stay **green** (slice isolation means neither sees it).\n- Coordinator's post-merge `just court-x2` goes **red**, and the flake-shifted failure signature names the seam.\n\nIf the slice catches it, the slices are not actually isolated (contract over-broad — tighten ownership). If court-x2 does not catch it, the gate is weaker than a full suite and this whole doc is wrong. Witness: the v26.10.14 compile-freeze receipts prove cross-lane interference is real, so the seeded case is representative, not contrived.\n\n## 5. Acceptance\n\n```\njust -l                          # `slice` recipe listed\njust slice 01                    # resolves WO doc, runs compile gate, runs owned slice\nprintf '## tests:\\n- test/nope.exs\\n' > /dev/null  # (contract-error path: `just slice` on a WO with a bad path exits non-zero, loud)\nbash scripts/court_x2.sh --dry-run 2>/dev/null || just court-x2   # unchanged; coordinator-only gate\n```\n\n- Every WO doc in `docs/jira/v26.10.15/` carries a `## tests:` block (grep-verifiable).\n- `just slice <bad-id>` exits non-zero with a resolution error.\n- Compile gate aborts a slice run when the shared tree does not compile.\n- Full-suite escalation table matches `_LANES.md` ownership + RESOLUTIONS seams.\n- Compile-freeze SLA text unchanged wherever it lives.\n\n## 6.
