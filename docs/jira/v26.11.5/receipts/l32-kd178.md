## Subject

KD-178 (CORE, docs/jira/v26.10.14/KNOWN_DIVERGENCES.md:359): broker restart wipes
client-visible state silently — broker (Smalt.WebPubSub GenServer) and Bandit listener are
separately supervised one_for_one children, so a supervised broker crash restarted the broker
with wiped groups registry/witness buffer while connected sockets kept riding the live Bandit
child: no disconnect, publish answers {:ok, 0} over dead membership, rejoin first-try. Real
Azure drops the client WebSocket on broker restart (reconnect+rejoin cycle).

## Fix (shim)

`lib/smalt/webpubsub/socket.ex` — `# KD-COVERS: KD-178` in moduledoc; socket now monitors the
broker in init/1 (Process.monitor on the whereis-resolved pid) and `{:stop, {:shutdown,
:broker_restarted}, state}`s on the :DOWN, closing the client WebSocket and forcing the real-Azure
reconnect+rejoin cycle. terminate/2 leave is now gated on Process.whereis/1 (a GenServer.call to a
dead broker name is an :noproc exit — the socket dies mid-restart). Close condition as written:
"link socket lifetime to broker death ... so a broker crash closes connected WebSockets, forcing
the real-Azure reconnect+rejoin cycle". `# KD-COVERS: KD-178` carried at the fix site
(lib/smalt/webpubsub/socket.ex).
