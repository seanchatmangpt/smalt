# generated-files-are-projections

Why a generated file has no independent truth, why hand-editing one is
always wrong, and how one incident proved it from both sides.

## The law

`~/ggen-marketplace`'s normative rule GGM-SRC-002 (quoted in
`~/.claude/skills/run-ggen/SKILL.md`): "Generated files MUST NOT silently
become a second source of truth merely because they are committed for
reviewability." If a generated file's content ever disagrees with what its
ontology+query+template would currently produce, fix the source and
regenerate — never hand-patch the generated file.

## Why hand-editing is always wrong

A generated artifact is the output of a function F(graph, queries,
templates). Hand-editing the output creates a second input source — the
editor's intent — that the function never sees. Three costs, all witnessed
this session:

1. The next regen silently deletes the hand-edit (the regen-overwrites
   half of the config.ex incident, below).
2. The graph no longer describes the running system, so every downstream
   consumer of the graph (capability docs, courts, other lanes reading the
   census) reasons from stale truth.
3. Nobody can distinguish landed law from drifted accident, because the
   provenance chain (graph row → query row → template block) is severed.

## The config.ex incident, both sides

`lib/smalt/config.ex` is generated by Chain 1 (config_keys.rq →
config.ex.eex; see
[the pipeline reference](../reference/smalt-generation-pipeline.md)).

- The regen-overwrites side (GGEN-CACHE, r11): config.ex carried committed
  R8 (`@neutral_aliases`/`neutral_env/1`, config.ex:20-37) and R9
  (`issuer_host`, config.ex:431/:712-718) blocks with no template backing.
  A fresh render (ggen_igniter wrote 167 rows in the lease) would NOT
  contain them. Regenerating would delete landed capability — so r11 typed
  the step BLOCKED and did not run it. The alternative (hand-adding
  redis_port into config.ex) was also refused: that manufactures a
  second source of truth.
- The fix-the-source side (GGEN-IDP, r12): R8's neutral-env block and the
  `smalt:ck-issuer-host` row were restored INTO the pack
  (`templates/config.ex.eex` + `ontology.ttl`), after which the
  regenerated config.ex measured HEAD + exactly three additive deltas and
  the three-test gate ran exit 0, `Result: 18 passed`.

Both lanes obeyed the same law from opposite directions: the artifact is
not where decisions live. The graph + templates are.

## What "committed for reviewability" buys

Generated outputs are committed so diffs are reviewable and gates run on
real trees — not so humans can edit them. The diff-vs-HEAD measurement
(r11's "+6 lines exactly"; r12's "three additive deltas") is the review
unit. A hand-patch has no such measurement against a generator, which is
precisely why it cannot be reviewed as a projection change.
