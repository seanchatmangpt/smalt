## Disclosures

1. **Transport pivot**: BEAM `:file` on a tty is unreliable on macOS (EBADF on
   write; UTF-8 translation corrupts bytes via `IO` without `binread`), and a
   pty slave cannot be the host's pyserial endpoint (slave->slave does not
   exist). Final architecture: host creates the pty and gives the BEAM the
   MASTER as its stdio (QEMU `-serial pty` pattern); pyserial opens the slave
   path like real hardware. BEAM `IO.binread/IO.binwrite` on stdio — raw
   bytes, no UTF-8 mangling.
2. **pyserial `in_waiting` shim**: during bring-up a master-side shim used
   select+FIONREAD; macOS pty masters misreport FIONREAD (0 with data queued).
   Removed with the pivot; production path is real pyserial on the slave.
3. **Gate2 without a device now FAILs (loudly), not SKIPs**, on hosts where
   pyserial sees macOS Bluetooth pseudo-ports: the SKIP "no device" path is
   unreachable there once `--device` works. The SKIP-loud branch remains for
   truly device-less hosts. Pre-landing the SKIP was an artifact of the typer
   refusing `--device` — the failure was masked, not absent.
4. `test_gates.py::test_gate2_uninvokable_flow_is_loud_skip_not_pass` was
   updated (disclosed in-file): pre-landing it asserted SKIP "not landed"
   (typer refused --device); post-landing a fake device path FAILs loudly.
5. Another lane's in-flight edit temporarily replaced the frame emit CRC
   check with a tautological `true <- true`; restored to the real CRC
   comparison. Any concurrent edits to `lib/smalt/hw/frame.ex` re-run these
   courts.
6. sim_host child launch bypasses mix (direct `elixir --pa` over
   `_build/dev/lib/*/ebin`, falling back to `mix run --no-start`) to avoid
   the shared `_build` lock contention observed during this wave (a `mix
   deps.get` at 450% CPU held it for 15+ min).
7. BEAM cannot open a pty; the host (Python) must create it. socat is absent
   on this host, ruling out the socat variant of the explore design.
