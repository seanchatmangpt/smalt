## Three-plane Define (DMEDI Define plane)

The takeover is partitioned across three planes, never a monolithic
"compatibility" claim:

1. **Standards-native partition log** — the canonical surface. The AoQ
   partitioned plane (rings, cursor atomics, partition workers, sealed
   admission, BLAKE3-chained receipts) is the primary log. Wire faces
   (Kafka, later Kinesis/SQS/gRPC) project onto it; they never fork the
   log.
   Falsifier for any wire face: a real client roundtrip through the face
   that the native log cannot absorb without a per-face fork in `lib/`.
2. **posh wire-compat faces** — the Kafka face lives in
   `lib/smalt/messaging/kafka/` as a BEAM-native wire face (group family,
   SASL, produce/fetch) speaking protocol version X to real clients
   (kafka-python-ng probes). "Wire-reachable at protocol version X" is the
   only lawful compat claim; "Kafka-compatible" is banned from this
   milestone's docs.
   - Protocol version surface (measured from the vendored client's
     protocol module): Produce=0, Fetch=10 v10? — UNMEASURED at authoring
     time; the api-key matrix in `lib/smalt/messaging/kafka/wire.ex` is
     the ground truth, not this doc.
   - The `posh` membrane hosts the per-vendor dialects (Azure Dialect #1);
     the Kafka face is BEAM-native, not a posh dialect — the standards
     graph stays zero-proprietary.
3. **AoQ native plane** — rings/partition workers/admission/projector as
   landed in v26.11.5 + this wave's additions (partitioned plane, QUIC NIF
   client face, batch SHACL admission, RDF projector, BLAKE3 gen-2 chain,
   lakehouse IPC mount). This plane is what every wire face lands on.

Every claim in this doc and `_LANES.md` is measured-only: each row is
receipt-pinned or explicitly UNMEASURED. Wire-compat rows cite the
protocol version the face speaks, never a vendor name as compatibility.
