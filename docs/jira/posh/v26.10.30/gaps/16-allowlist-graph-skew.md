# GAP-16: Allowlist graph-vs-config skew

Status: PARTIAL (skew confirmed by live probe + read trace; no posh.yaml projection exists)

## The skew (GAP4/GAP8)

Three surfaces state the egress allowlist:

1. **Turtle graph** (declared topology): `packs/posh/examples/posh_instance.ttl:79-80`
   and `packs/posh/ontology/routes.ttl` — `posh:sinkStarboard9443 a posh:Sink ;
   posh:deliverTo "http://127.0.0.1:9443"`. The graph admits 127.0.0.1:9443.
2. **Generated Go ops** (graph projection): `posh/internal/adapter/generated_ops_arm_get.go:10`
   (and all 14 generated op files) — `AllowHosts: []string{"http://127.0.0.1:9443"}`.
   Header: "Code generated by ggen from packs/posh/ontology/posh.ttl — DO NOT EDIT."
3. **Shipped posh.yaml** (runtime fence): `posh/posh.yaml:18` — `egress_allowlist: []`,
   and `posh/internal/config/config.go:58-61` fail-closes on a missing/empty file
   (POSH-008). Also: validation (config.go:84-87) rejects entries containing `/: @`,
   so the generated URL-shaped `http://127.0.0.1:9443` could never be a yaml entry
   as-is — only bare `127.0.0.1` would admit it.

## Runtime path (read trace)

`generated_dispatcher.go` (`deliver`, line 50) gates delivery on
`egress.AdmitsHost(cfg, m.AllowHosts[0])` — the graph-projected AllowHosts value is
the *requested* host; **posh.yaml is the runtime enforcement authority**. The
`AllowHosts` literal is never compared against the graph at runtime; the graph only
shaped the generated literal. `egress.go:150-156` (DialContext) and `:174-177`
(redirects) consult `cfg.EgressAllowlist` exclusively.

**Deeper finding: the dispatcher is dead code in the shipped binary.**
`cmd/posh/main.go:30-32` defines `var ops = map[string]server.Handler{"echo": echoOp}` —
only `echo`. Nothing outside `internal/adapter` references `adapter.Dispatch` (grep over
all non-test .go: zero hits). The generated ops never reach the live membrane.

## Live probe (witness receipt)

Built `bin/posh` from HEAD (`go build ./cmd/posh`, exit 0), booted with the shipped
posh.yaml (`./bin/posh -config posh.yaml`, socket `run/posh.sock`, boot log:
`{"level":"INFO","msg":"listening","socket":"run/posh.sock"}`), sent a length-prefixed
UDS frame `{"id":"gap16-1","op":"arm-get",...}`:

```json
{"id":"gap16-1","error":{"code":"UPSTREAM","message":"unknown op \"arm-get\""}}
```

Expected per graph: delivered to 127.0.0.1:9443. Expected per yaml fence: REFUSED_EGRESS.
Actual: **unknown op** — the request died at the op-registry layer *before* the egress
fence. So the graph-vs-yaml skew is real but currently unobservable through the live
surface: the generated dispatcher is not wired in. (REFUSED_EGRESS was not witnessed;
the refusal happened one layer earlier.)

## Verdict

- **Authority for runtime enforcement: posh.yaml** (config.go fail-closed POSH-008;
  egress.go consults only cfg). Unambiguous — every live path reads cfg.
- **Authority for declared topology: the Turtle graph** (`posh:Sink posh:deliverTo`),
  projected into generated code but NOT into posh.yaml.
- **The skew is a false invariant claim, not an open fence.** `construct_go_adapter.rq:6`
  asserts: "Allowlist in binary and posh.yaml cannot drift: both are projections of this
  graph." No template projects posh.yaml — the pack templates are only
  `beam_pipeline.ex.tmpl`, `go_dispatcher.go.tmpl`, `go_membrane_op.go.tmpl`. The yaml is
  hand-written and ships `[]`. Safety direction is fail-closed (yaml denies; graph admits
  a loopback host only), so severity is **low** as a security exposure, **medium** as a
  documented-invariant lie: a future "flip the yaml" action has no graph-consistency
  court, and the CONSTRUCT header would mask it.

## Close condition

1. Add a ggen template (e.g. `posh_yaml.tmpl`) projecting `egress_allowlist` from
   `?sink posh:deliverTo ?host` (bare-hostname normalization, since config validation
   rejects scheme/port) so graph and yaml cannot drift — then the CONSTRUCT header's
   claim becomes true.
2. Wire `adapter.Dispatch` into `cmd/posh`'s ops registry (or delete the dead generated
   dispatcher) so the runtime surface matches the graph surface; until then the arm-get
   op is graph-admitted but binary-absent.
3. Court: re-run the UDS probe above; expected outcome after close is REFUSED_EGRESS
   (graph admits, yaml denies, fence fires) or delivery to a real loopback sink after a
   graph-driven yaml flip — never "unknown op".
