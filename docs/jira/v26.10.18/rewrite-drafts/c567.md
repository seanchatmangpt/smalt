## 1. C5 (`c5_servicebus.exs`) — port save/restore consolidation

### Current shape (c5_servicebus.exs:343-404)

The `live broker session` setup hand-rolls a save-prev/restore block for four
port envs (`:arm_port`, `:egress_port`, `:amqp_port`, `:event_hubs_port`),
carrying the saved tuple across the setup/on_exit scope seam via the process
dictionary (`{__MODULE__, :ports_prev}`), then a ~20-line conditional
delete-or-put per key in on_exit. c7_events.exs repeats the identical pattern
for three keys (lines 24-61). egress_dispatch_test.exs:2721 has a third copy.

### Proposed canonical helper (additive, in `SmaltTest.Lifecycle`)

```elixir
# test/test_helper.exs, inside defmodule SmaltTest.Lifecycle
@doc """
Save the given :smalt Application env keys, hand back an opaque token.
`restore_envs/1` in on_exit reverses exactly the saved state: keys that were
unset at save time are deleted, keys that were set are put back byte-exact.
Non-raising — safe from on_exit.
"""
def save_envs(keys) do
  saved = Map.new(keys, fn k -> {k, Application.get_env(:smalt, k)} end)
  token = {__MODULE__, :env_guard, make_ref()}
  true = Process.put(token, saved) == nil
  token
end

def restore_envs(token) do
  case Process.get(token) do
    nil ->
      :ok

    saved when is_map(saved) ->
      Enum.each(saved, fn
        {k, nil} -> Application.delete_env(:smalt, k)
        {k, v} -> Application.put_env(:smalt, k, v)
      end)

      Process.erase(token)
      :ok
  end
end
```

## 3. C7 (`c7_events.exs`) — fresh-partition fence, deterministic unique-id helper

### Problem

The fresh-partition fence (c7_events.exs:269-270) draws partition names from
`System.unique_integer([:positive])`, which is unique but NONDETERMINISTIC —
re-runs get different keys and the freshness property the fence depends on
(seq == 1 requires a never-before-used partition key, because the
`Smalt.Messaging.EventHubs.Server` seq counters are immortal across the
per-test Store restart) is implicit in a comment, not named by the code.

### Proposed helper (additive, in `SmaltTest.Lifecycle`, same seam as §1)

```elixir
# module attribute, evaluated once at test_helper load (per mix test process)
@run_seed :erlang.phash2(:erlang.make_ref())

@doc """
Deterministic unique id: `uid(prefix)` -> "#{prefix}-<run_seed>-<serial>".

- Deterministic within a run for a given call sequence: replaying the same
  call sequence in the same run reproduces the same ids (failure replay).
- Unique across runs: the run_seed differs per `mix test` process.
- Unique across call sites within a run: monotonic per-process serial.

This names the exact property the c7 fresh-partition fence needs
(never-before-used partition key) instead of leaving it implicit in
`System.unique_integer/1`.
"""
def uid(prefix) do
  n = :atomics.add_get(uid_counter(), 1, 1)
  "#{prefix}-#{@run_seed}-#{n}"
end

defp uid_counter do
  case :persistent_term.get({__MODULE__, :uid_counter}, :missing) do
    :missing ->
      ctr = :atomics.new(1, signed: false)
      :persistent_term.put({__MODULE__, :uid_counter}, ctr)
      ctr

    ctr ->
      ctr
  end
end
```

Concurrent-lane note: each `mix test` process loads test_helper once, so
`@run_seed` differs per lane; the lane-local monotonic serial covers
within-run uniqueness. No cross-lane collision on the shared checkout.

### Resulting c7 usage (c7_events.exs:269-270)
